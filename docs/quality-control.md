# Контроль качества сохранённого разбора

`laboratory.quality_audit` проверяет сохранённые основания без нового исследования. Он не вызывает модель, CLI, захват источников или сеть, не меняет исторический ответ и не одобряет публикацию. Чтение API может безопасно пересчитать результат из существующих записей.

## Интерфейс

```python
from laboratory.quality_audit import audit_saved_quality, summarize_audits, run_control_corpus

audit = audit_saved_quality(run, presentation, review)
summary = summarize_audits([audit])
controls = run_control_corpus()
```

`run`, `presentation`, `review` — уже прочитанные словари. Если `presentation` не передан, используется только локальный `build_presentation(run, review)`. Все функции возвращают JSON-совместимые значения, не пишут в базу и не изменяют входные словари. `review` участвует в построении редакторской версии; ручные баллы рубрики не превращаются в научную оценку.

Версия результата — `saved-quality-audit-v1`. `findings` содержит стабильный `id`, именованный `facet`, `severity`, `status`, `category`, `evidence_pointer` и объяснение `detail`. Указатель имеет форму JSON Pointer относительно контейнера `{"run": ..., "presentation": ..., "review": ...}`. Это место проверки, а не доказательство истинности.

Статусы:

- `pass`: применимая наблюдаемая проверка сохранённой записи пройдена.
- `needs_review`: обнаружен пробел, противоречие, неподтверждённое число или ненаблюдаемое исправление.
- `not_applicable`: проверка неприменима, например нет численной пары, либо независимая научная проверка выходит за границы автоматического аудита.

`overall_status` становится `needs_review`, если есть хотя бы одно такое замечание. Пустые основания не дают `pass`: отсутствие реестра, оригинальных привязок или проверки формата отмечается явно. `counts` и сводка считают записи/замечания, не качество науки. Численных рейтингов, средних баллов и автоматического допуска к публикации нет.

## Что проверяется

| Аспект | Проверяемое основание | Граница вывода |
| --- | --- | --- |
| Формат | Завершённый ответ и существующие `publication_checks` | Полнота формата не подтверждает факты |
| Факты | Уникальный реестр, хеш отчёта, цитата в основном тексте, известный публичный URL | Дословное присутствие не доказывает семантическую поддержку |
| Источник | Повторный `validate_checks` по замороженному `evidence_bundle`; тот же документ, сегмент, цитата и URL | Хеш и URL не удостоверяют издателя; выбранные сегменты не означают чтение всего документа |
| Числа | Число в связанном фрагменте отчёта и оригинала, сохранённая модельная связь `supports` | Наличие числа не подтверждает измерение, причинность или определение метрики |
| Сопоставимость | Существующий `validate_applied`, точное соответствие графика единице/условиям/основаниям, заполненный `measurement_context` | Заполненные условия не доказывают эквивалентность экспериментов |
| Применимость | Явные задача, адресат, сценарий, вывод, границы и следующий шаг | Успех в рабочем проекте не установлен |
| Self-hosted и стоимость | Явные ресурсы и конкретная неизвестность либо записанная неприменимость | Пригодность GPU, лицензия и полная стоимость не угадываются |
| Критик | Ровно одно решение на замечание, дословный наблюдаемый фрагмент исправления, связь сохранённой проверки с финальным ответом | `fixed`, согласие модели и ручной балл не заменяют научную проверку |

Явно несопоставимая или неизвестная строка допустима в таблице с объяснением; она не создаёт право на график эффективности. Механизм без численной пары допустим при сохранённой причине отсутствия данных. `contradicts` и `insufficient` остаются замечаниями даже при правильной дословной цитате.

`source_provenance.level` — словесный уровень происхождения, а не вероятность: `original_segments_bound`, `saved_report_only`, `missing_or_unread`. В каждом случае `independently_verified` остаётся `false`. Историческому протоколу не приписывается новая проверка оригиналов.

## Контрольный корпус

`control_corpus()` создаёт десять синтетических случаев только в памяти. Все имеют префикс `TEST_ONLY`; они не являются историческими исследованиями и не сохраняются как результаты. `run_control_corpus()` возвращает ID случая, ожидаемые и наблюдаемые статусы, совпадение ожидания и количество совпавших случаев.

| Случай | Ожидаемая реакция |
| --- | --- |
| Числа с точными привязками | Проверки чисел и оригинала проходят |
| Число отсутствует в цитате | Численная привязка требует проверки |
| Разные условия, но оставлен график | График отклоняется как несоответствующий строке |
| Нет сохранённого первоисточника | Привязка оригинала требует проверки |
| Текст оригинала не извлечён | Отмечены непрочитанный текст и незавершённая привязка |
| Неразрешённый blocker критика | Требуется проверка решения |
| `fixed` без наблюдаемого исправления | Одной пометки недостаточно |
| Механизм без численной пары | Численная проверка неприменима, схема разрешена |
| Неизвестная полная стоимость self-hosted | Честная неизвестность допускается |
| Нет оценки оригинальных сегментов | `ready` формата не скрывает пробел |

Это измеримая проверка детекторов на заданных дефектах. Даже десять совпавших случаев не являются оценкой научной точности реальных исследований.

Проверка офлайн:

```text
python -m unittest discover -s tests -p test_quality_audit.py
```

Тесты блокируют сокеты, запуск подпроцессов и захват источников; проверяют детерминизм, неизменность входов, несовпадение числа/URL/цитаты, неподтверждённый `fixed`, пустые основания и разделение формата с научной истинностью. Обычный read API использует функции выше и не запускает эту команду.
