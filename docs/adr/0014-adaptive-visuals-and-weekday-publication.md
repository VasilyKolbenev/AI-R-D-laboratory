# ADR-0014: adaptive evidence-led media and five owner-approved weekday slots

The owner requested five releases weekly and meaningful visual variation by news. Configure the existing local VV Frontier queue for Monday–Friday at 12:00 Europe/Moscow. The setting authorizes scheduling only: a frozen package still requires its owner's exact Telegram «В очередь» callback. Empty slots are skipped, missed slots do not cause catch-up bursts, and no schedule initiates research. Keep fresh-install defaults disabled and preserve the existing research cap. A running local application and network are required.

Add a deterministic adaptive-v1 visual profile to eligible reader presentations. A supported baseline/result comparison selects charts; otherwise select a mechanism diagram, infrastructure/resource stack, or text-led applicability board. An optional bounded enum visual_focus is supplied in the existing research response. It cannot create numeric support or change a chart's factual requirements. Saved reports use conservative semantic routing from their existing public fields, without another provider call. Preserve legacy raw extraction and specialized replay rendering.

Use distinct compositions and animation emphasis, rather than cosmetic color rotation. Never invent scale, baseline, hardware, cost, effect, or elapsed experiment timing. Keep selected source wording, conditions, unknowns and citation provenance readable at native 1080 px. Motion explains sequence, deployment layers or a briefing; it is not a measured performance claim. Reject oversized video layouts rather than truncate or shrink source conditions.

The visual profile, label and reason are part of the rendered presentation and thus its publication signature. Show them in the local result and owner-only queue control, not inside the public post. Do not alter the saved original report, editorial journals, approvals or usage. Previously published packages retain their frozen files and delivery receipts; this change does not republish them. A changed unposted package needs a fresh preview and approval.

Verify conservative classification, optional enum validation, unsupported-comparison fallback, replay/legacy compatibility, distinct native media layouts, actual MP4 decode, source/condition retention, owner preview separation and the existing suite. Render examples from already saved reports without creating reviews, provider calls or Telegram sends.
