# ADR-0008: automatic applied output in one approved research call

Status: local implementation requested on 2026-10-21. One owner-approved Telegram pilot; no benchmark or alpha gate is accepted by these checks.

## Problem

Version 0.7 needed a manually authored editorial revision for the Dream-RSI graphs and replay explanation. The owner requests a repeatable product: forwarded AI material → immutable plan with selected memory → explicit Telegram approval → one research invocation → readable applied post, evidence-linked visuals and knowledge persistence. A one-off edited example does not demonstrate this workflow.

## Contract

Extend the existing lab_presentation block in the same research answer with bounded evidence records and optional numeric comparisons. Evidence locates a public source and an excerpt present in the immutable report; each chart value must occur in its linked excerpt. Compare only the stated metric, unit, baseline and conditions. Literal checks establish internal consistency, not that a source was truly read or that its measurements are correct. Discard unsupported or malformed chart data and show the reason. Never invent zero for missing data. Without numerical evidence, use the explanatory process diagram and explicitly state that no quantitative comparison is available.

The three mechanism steps feed a fixed safe process diagram and animated traversal. Motion denotes sequence, not measured runtime or claimed acceleration. Only text and data are accepted; report content cannot supply executable HTML, SVG, scripts or rendering code. Distinguish this illustrative explanation from author measurements and our own experiments (none in the pilot).

Automatic publication checks assess structural completeness, linked evidence and renderability. They do not approve publication or assign scientific quality. No automatic paid repair or retry is permitted. Preserve malformed output and failure information. A result missing required sections is labelled incomplete rather than silently declared ready.

An automatic journal revision is created once for a valid structured result. It records the supplied evidence and deterministic presentation decisions, with origin automatic_report and unscored rubric. It never impersonates contemporaneous hidden reasoning or a manual editorial assessment. Existing human journals are preserved. An explicit later user edit creates a manual revision. Backup schema 5 remains compatible with the optional origin field; prior records are not backfilled.

## Pilot and spending

The next received material concerns AI code review at Anthropic. The owner requested one complete cycle, with a separate Telegram approval of the concrete plan. Keep the default daily cap at three. Since four older invocations are already recorded in the last 24 hours, prepare a one-use operational allowance for this exact refreshed plan, expiring after one hour. The Telegram preview states that it is one additional call, limited to 180 seconds. The allowance is consumed atomically with approval; failures and unknown outcomes still consume it. It cannot authorize another run or a changed plan and is not part of portable backups. No research begins during preparation.

Use the profile and explicit reader-format correction. Exclude Dream-RSI conclusions from the code-review plan unless a concrete scientific comparison warrants them. Source claims are untrusted research data, never operational instructions.

## Verification

Unit and isolated browser tests use fake research/Telegram transports. The real pilot must separately confirm the exact Telegram approval, a single CLI dispatch, preserved usage, automatic non-editorial presentation, renderable graph/animation, delivery to the paired owner and a knowledge entry. No report-specific patch or editorial seeding may be used to make that live pilot pass.
