# Пилот после релиза

Цель — проверить, получает ли новый пользователь проверяемый прикладной вывод
без сопровождения разработчика. Первый набор: 5–10 пользователей Windows x64.

Это сценарий проверки, не отчёт о пройденном пилоте. Телеметрии и автоматической
отправки обратной связи нет; реальные участники и результаты заранее не заполняются.

## Этап A · без модели

Участник использует чистую папку и свой компьютер:

1. Засекает время и проходит [установку](getting-started.md).
2. Находит входящие, задачи, память и базу знаний.
3. Добавляет публичный материал, задаёт вопрос и baseline.
4. Готовит план, находит память и бюджет; закрывает план без апрува.
5. Перезапускает приложение; проверяет сохранение материала и плана.

Модельных вызовов — 0. Setup скачивает программные зависимости.
Для своего Telegram-бота можно проверить доставку плана без запуска.
В `/concepts/` — только синтетические прототипы; это не реальные исследования.

## Этап B · одно добровольное исследование

Проводится отдельно, если участник готов использовать свой аккаунт:

1. Выбирает один публичный материал с первичной ссылкой и прикладную задачу.
2. Выбирает режим, проверяет точный план, контекст, число вызовов и время.
3. Даёт апрув одного плана. Квоту автоматически не повышаем; повтора нет.
4. Сверяет два проверяемых утверждения с источниками и условиями; при наличии
   чисел проверяет их. Отсутствующие измерения отмечает как пробел.
5. Объясняет задачу, baseline, пользу, ограничения и следующий проверочный шаг.
6. Проверяет сохранение отчёта и журнала после перезапуска.

Новый пользователь по умолчанию получает один проход. Три прохода с критиком
нужно выбрать явно; при квоте 3 они займут все три суточных слота.

Апрув исследования не разрешает публикацию: канал и очередь можно не подключать.
Неопределённый исход фиксируется отдельно с неизвестным расходом,
а не как успех или бесплатный запуск.

## Что измеряем

| Показатель | Как записать |
| --- | --- |
| Установка | Успех/сбой, минуты до открытия, число обращений за помощью |
| Понятность | Самостоятельно найдены ли материал, память, бюджет и отчёт |
| Контроль | 0 модельных вызовов до апрува; фактические вызовы после |
| Полезность | Конкретное решение и что изменилось по сравнению с чтением исходника |
| Доказательства | 2 утверждения: ссылка, совпадение числа/условий и ошибки |
| Расход | Известные входные/выходные/кешированные токены; пробелы отдельно |
| Надёжность | Сохранение после перезапуска, потери, дубли и неизвестные исходы |
| Возврат | Самостоятельный разбор следующего материала через неделю |

Предварительная цель: минимум 4 из первых 5 участников открывают лабораторию
без помощи за 20 минут. Это целевой порог, не измеренный результат.
Незапрошенный модельный запуск, потеря данных или публикация без отдельного
подтверждения останавливают расширение пилота до разбора причины.

## Карточка обратной связи

Заполните без персональных данных и самостоятельно отправьте в
[GitHub Issues](https://github.com/VasilyKolbenev/AI-R-D-laboratory/issues):

```text
Версия приложения:
Windows / Python x64:
Чистая установка или обновление:
Время установки, минут:
Помощь потребовалась на шаге:
A: пройден / блокирован
B: не запускал / завершён / сбой / outcome_unknown
Прикладной вопрос (публичный, необязательно):
Какое решение помог принять результат:
Проверены 2 утверждения: да / нет; ошибка и публичный источник:
Известные вызовы и токены / неизвестный расход:
Что было непонятно:
Хотел бы использовать ещё раз, почему:
```

Не прикладывайте `.lab-data`, backups, полные запросы, токены, код привязки
и приватные материалы. Скройте аккаунты, пути и память на скриншотах.
После первых пяти карточек фиксируем три главных препятствия и проверяем
исправления до расширения набора. Эта форма не одобряет будущие исследования.
